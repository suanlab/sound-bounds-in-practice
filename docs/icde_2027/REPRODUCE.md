# Reproducing the ICDE 2027 (EAB) results

**Paper:** `docs/icde_2027/paper.tex` — *[Experiment, Analysis, and Benchmark] Sound Cardinality Bounds in
Practice: Guards, Estimates, and Plan Certificates*. `docs/icde_2027/CLAIMS_EVIDENCE.md` maps every claim to its
value, interval and status. `PYTHONHASHSEED=0 python -m experiments.scripts.audit_icde_numbers` re-derives every
headline number from `results/` and checks it against the LaTeX source.

Provenance logs (`docs/AUDIT_REPAIR_LOG.md`, `results/SUPERSEDED.md`) and the frozen pre-registration
(`docs/c4_preregistration.md`) refer to earlier internal drafts of this work; none of them was submitted to any venue.

## Environment
```bash
python -m venv .venv && source .venv/bin/activate     # tested on CPython 3.10.12, Linux
pip install -r requirements-lock.txt                  # exact pins (or requirements.txt for loose)
```
All wall-clock numbers (certificate cost ratios, DuckDB/SQLite plan runtimes,
the runtime-scalability section) were measured on one **shared, otherwise-loaded**
machine: 2× Intel Xeon Gold 5218R @ 2.10 GHz (40 threads), 251 GB RAM, Linux,
CPython 3.10.12 (single-threaded), DuckDB 1.5.4, SQLite 3.37.2. Ratios within a
run are the reported quantity; absolute times are not comparable across runs
and no timing number should be read as a deployment figure.

## Determinism
Export `PYTHONHASHSEED=0` for every run. Synthetic generation is seeded
(`Random(seed)`), but the pessimistic-bound computation iterates over `set`/`frozenset`,
whose order depends on `PYTHONHASHSEED`; fixing it to 0 makes the committed numbers
bit-reproducible. All committed result JSON was produced with `PYTHONHASHSEED=0`.

## External artifact (baselines)
Some tables consume the SIGMOD'25 **LpBound** reproducibility artifact, which ships
per-query estimates for real JOB-light / STATS-CEB *and* the raw STATS tables:
```bash
git clone https://github.com/fdbresearch/LpBound.git external/LpBound
git -C external/LpBound checkout ee01ad5d9ff0277c0e964a23e222cc1b4f522aa3
```
`external/` is untracked; it is a read-only baseline source (we do not modify it).
All committed results were produced against commit `ee01ad5d` of that repository
(ground truth, the eight proposals, both upper certificates, and the raw STATS
tables all come from it); a moving branch would silently change them.

**Correctness notes.** Cross-validating our exact counts against that artifact's
ground truth exposed independent data-handling defects. They were found only because an
external ground truth (or a loud loader check) was available, and all are now
covered by regression tests.

1. *NULL join keys* (`src/utils/join_counting.py`): NULL was treated as an
   ordinary value, so NULL-keyed rows joined with each other (`votes.UserId` is
   89% NULL on STATS-CEB → up to **86x** inflation). Fixed by dropping NULL join
   keys, since `NULL = NULL` is never true.
2. *PostgreSQL CSV quoting* (`src/utils/imdb_schema.py`): the IMDb dump follows
   the `QUOTE '"' ESCAPE '\'` convention, where a backslash escapes the next
   character **only inside a quoted field**. Python's `csv` cannot express that:
   the default splits `"\"Hatikva\" neighborhood, Tel Aviv, Israel"` in
   `movie_info.csv` into three fields (5-column row becomes 7), while
   `escapechar='\\'` swallows the delimiter after the unquoted title
   `\Frag'ile\` in `title.csv` (12-column row becomes 11). DuckDB's CSV reader
   implements the PostgreSQL rule and is used as the parser. The loader's
   field-count check is what surfaced both cases instead of mis-aligning columns
   silently.
3. *NULL in comparison filters* (`src/utils/job_sql_parser.py`): a non-numeric
   cell fell back to string comparison, and `"" <= "100"` is lexicographically
   true, so NULL rows passed predicates such as `v.BountyAmount<=100` and
   `p.FavoriteCount<=27`. SQL evaluates those to UNKNOWN and drops the row.
   This affected 11 of 130 STATS-CEB queries by up to **97x**.

After these fixes our exact counts match the artifact ground truth on every
cross-checked query. The committed synthetic/fixture data contains no NULLs, so
previously committed synthetic/fixture results are unaffected.

## Data notes
- **JOB-medium / JOB-light are SYNTHETIC IMDb-like fixtures** (`data/job_medium`,
  `data/job_light`), generated by `generate_job_medium.py`; they are not the real JOB
  benchmark. True cardinalities are computed by executing the join exactly
  (`src/utils/join_counting.count_join`), independent of any estimator.
- Real JOB (IMDb + 113 query templates) is prepared by `prepare_real_job.py`.
  The SQL→(aliases, joins, filters) parser is implemented
  (`src/utils/job_sql_parser.py`, 111/113 templates parse; alias-keyed so self-joins
  work) and the runner is `run_job_real.py`. The full run is memory-heavy (tens of
  GB of Python objects) and is therefore executed locally rather than in CI.
- **Real STATS-CEB** (146 queries, raw tables from the LpBound artifact) parses
  146/146 with no parser changes and is the basis for the certificate-utility tables.

### PostgreSQL with sub-plan injection (`experiments/pg_injection/`)
1. Build: `bash experiments/pg_injection/prepare_build.sh` downloads PostgreSQL 13.1
   (`postgresql-13.1.tar.bz2`, sha256
   `12345c83b89aa29808568977f5200d6da00f88a035517f925293355432ffe61f`, checked), applies
   `external/End-to-End-CardEst-Benchmark/benchmark.patch` (commit 670cb8d4), repacks it and
   copies `experiments/pg_injection/docker/{Dockerfile,init_pgsql.sh}` into
   `experiments/pg_injection/build/`; then `cd experiments/pg_injection/build && docker build -t ceb-opt .`
   (the benchmark's Dockerfile with `-O2`, no cassert, apt sources on archive.debian.org, and
   `pg_hint_plan` from `github.com/Nathaniel-Han/pg_hint_plan` pinned to commit
   `a6052904d08d351b50501af079da8b75a2c3382e`). The image we measured with was built from the same
   Dockerfile before the pin was added; the pinned commit is the one found in that image. The
   `debian:buster` base image is end-of-life and not pinned by digest.
   Run: `docker run --name ceb-icde -p 127.0.0.1:55432:5432
   --cpuset-cpus=36-39 --memory=24g -v $PWD/external/End-to-End-CardEst-Benchmark:/bench:ro -d ceb-opt`;
   load STATS with the benchmark's `stats.sql`, `stats_load.sql`, `stats_index.sql`, then `ANALYZE`
   (IMDb for JOB-light: `experiments.pg_injection.load_imdb`).
2. Driver dependency: `psycopg2-binary` (pinned in `requirements-lock.txt`).
3. Credentials: the scripts' default DSN uses the container's local password (`postgres`); the server is
   published on `127.0.0.1` only. Pass `--dsn` to use other credentials. Some planning-only scripts
   (`native_estimates_incontext`) need superuser rights (`COPY TO`, `pg_read_file`). The Dockerfile now
   creates the password file owned by `postgres` with mode 600 (the measured image used mode 777; this
   change has not been rebuilt yet).

Timing protocol: queries start when the 1-min load average is < 60 (≤ 30 min wait, flagged otherwise),
plans of a query run interleaved ×3 (`--always-reps`; a plan that times out is not re-run), 300 s timeout, the
